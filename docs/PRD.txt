# PRD: Single-Room Multi-User Coin Pusher (PoC 版本, Rev B)

Platform: Mobile Web  
Frontend: TypeScript + ReactJS UI + BabylonJS (render) + Rapier (WASM physics)  
Backend: TypeScript (Node.js) • Authoritative Server (單房) • WebSocket Push  

目標：快速驗證「多人即時互動 + 伺服器權威物理模擬」可行性，降低開發成本，保留最必要的技術路徑。

------------------------------------------------------------
1) PoC 核心目標
------------------------------------------------------------
✅ 驗證 Rapier 在瀏覽器與 Node.js 雙端物理模擬表現  
✅ 驗證 BabylonJS + Rapier 同步流程（右手座標 + 四元數）  
✅ 實現「多人同房投幣」即時互動與同步視覺化  
✅ 測試 WebSocket 穩定性與簡易同步插值效果  
✅ 新連線世界快照（world_snapshot）與移除事件（despawn）  
❌ 不追求完整遊戲體驗（得分、登入、重連等可暫略）

3) 遊戲流程（PoC 簡化）
------------------------------------------------------------
1. 玩家打開頁面即加入唯一房間。  
1.1 伺服器立即回傳 `world_snapshot`（現存剛體完整清單, 含推板）。  
2. 點擊「Insert Coin」→ 傳送 `{ op: "coin_insert", x }` 給伺服器。  
   - `x` 範圍：-0.5 ~ 0.5（公尺），表示投幣橫向位置
3. 伺服器生成硬幣（高度固定，如 y=1.5m；自由落體階段啟用 CCD）→ Rapier 模擬 @30Hz，substeps=2 → 每 33ms 廣播狀態。  
4. 推板以正弦運動沿 **z 軸** 往返（振幅 0.3m，頻率 0.5Hz），以「next kinematic translation」更新。  
5. 所有玩家畫面同步看到硬幣掉落、推板運動（客端僅渲染，不本地模擬）。  
6. 無計分、無重連；硬幣 `y < -0.1m` → 伺服器廣播 `despawn`，客端移除。  
7. 重新整理即重置狀態。

4) 技術要點（保留重點）
------------------------------------------------------------
A. 座標系統統一（右手系）  
- Client：`scene.useRightHandedSystem = true`（明確設定）  
- Rapier：預設右手 + Y-up  
- 位置直接同步，旋轉只傳四元數  

B. 統一四元數流程（必保留）  
伺服器推播（位置/旋轉量化至小數3位；四元數每次 normalize）：
{
  "id": 1,
  "pos": [0.1, 0.3, -0.2],
  "rot": [0.000, 0.707, 0.000, 0.707]
}
客端設定：
mesh.rotationQuaternion = new Quaternion(qx, qy, qz, qw);
禁用 rotation.x/y/z，避免萬向節。

C. 時鐘同步與插值緩衝（簡化保留）  
- 伺服器在每條 state_delta 回傳 serverTime（ms）。  
- 客端連線時發送 ping，伺服器回 pong + serverTime，計算 RTT。  
- Offset 估算：取最近 5 次 RTT 的中位數，offset = (serverTime - clientTime) - RTT/2  
- 固定延遲顯示 **100–120ms**：用邏輯時間 `t = now() + offset - delay` 在緩衝區插值。  
- 插值策略：
  - 位置：線性插值 `lerp(p1, p2, alpha)`（量化值）
  - 旋轉：Quaternion.Slerp（量化值）
- 不實作丟包偵測或動態 buffer。

D. 推板運動（Kinematic）  
- 伺服器每 tick 計算 z = A*sin(2π f t + phase0)；  
- 以 **setNextKinematicTranslation**（或對應 API）更新推板位置；  
- 下行廣播 **`pusherZ`**（或 phase），避免把推板當一般剛體塞進 bodies。

E. 穩定性參數（Rapier）  
- 伺服器 30Hz + **substeps=2** 或 solver iters：vel=8, pos=3；  
- **CCD 只在自由落體階段開啟**，落盤且速度低於閾值後關閉；  
- 啟用 sleep（睡眠門檻）降低長時間堆疊的求解壓力。

5) 系統架構（PoC）
------------------------------------------------------------
[Client (React+Babylon)]
        ⇅ WebSocket(JSON; ID=整數, 數值量化3位)
[Node.js Server]
  - 接收 coin_insert（in-memory queue）
  - Rapier step() @30Hz（固定 deltaTime = 1/30, substeps=2）
  - 推板：kinematic + next translation（沿 z 軸正弦）
  - 每 tick 廣播：state_delta（bodies 更新 + pusherZ）
  - onConnect：先送 world_snapshot

6) 通訊契約（PoC, 量化版）
------------------------------------------------------------
上行：
{ "op": "coin_insert", "x": 0.200 }

下行（初次）：
{
  "op": "world_snapshot",
  "protocolVersion": 1,
  "serverTime": 1730345678000,
  "tick": 12222,
  "bodies": [
    { "id": 0, "type": "pusher", "z": 0.150 },
    { "id": 1, "type": "coin", "pos": [0.120,1.250,0.500], "rot": [0.000,0.707,0.000,0.707] }
  ]
}

下行（delta；推板獨立欄位）：
{
  "op": "state_delta",
  "serverTime": 1730345678150,
  "tick": 12345,
  "updates": [
    { "id": 1, "pos": [0.130,1.220,0.490], "rot": [0.000,0.700,0.000,0.710] }
  ],
  "pusherZ": 0.148
}

下行（移除）：
{ "op": "despawn", "tick": 12360, "ids": [17, 19] }

心跳（ping/pong）：
上行：{ "op": "ping", "clientTime": 1730345678100 }
下行：{ "op": "pong", "serverTime": 1730345678150 }

7) 數據結構（最小化）
------------------------------------------------------------
type BodyState = {
  id: number; // 整數ID
  type: "coin" | "pusher";
  pos?: [number, number, number];         // coin 專用
  rot?: [number, number, number, number]; // coin 專用
  z?: number;                              // pusher 專用（沿 z）
};

type WorldState = {
  protocolVersion: number;
  tick: number;
  serverTime: number;
  bodies: BodyState[];  // 包含推板（type="pusher"）與所有硬幣
};

// 硬幣生成參數
type CoinSpawnParams = {
  x: number;        // 投幣位置 x（範圍：-0.5 ~ 0.5）
  y?: number;       // 預設 1.5m
  z?: number;       // 預設 0（推板前方）
};

13) 非功能性需求（PoC 簡化）
------------------------------------------------------------
A. 一致性（必保留）⭐
- 伺服器結果唯一真實；客戶端僅渲染，不接受本地模擬結果。

B. 可測試性（簡化）⚠️
- 核心邏輯可被測試（事件處理、時鐘同步、插值）。

C. 可維護性（簡化）⚠️
- 模組邊界清楚（client/scene/net, server/physics/game）。
- 共用型別集中於 shared/（手動同步即可）。
- protocolVersion 檢查以避免前後端不一致。

D. 可觀測性（最簡化）❌
- ✅ Console.log 輸出關鍵事件與錯誤 + 粗略封包大小。
- ✅ FPS counter（客戶端）。

------------------------------------------------------------
14) 併發與公平性（PoC 簡化）
------------------------------------------------------------
A. 速率限制（簡化）⭐
- ✅ Per-connection：每個 WebSocket 連線每秒最多 1 次投幣。
- ✅ 伺服器側座標檢查：x ∈ [-0.5, 0.5]，越界丟棄。
- ✅ 100ms 時間窗，同連線最多 1 次投幣（去抖）。
- ❌ 移除 Token bucket/Per-IP。

B. 服務保護（最簡化）❌
- ✅ 投幣請求過多 → 丟棄並 console.warn。
